
# Инструкция по установке и использованию

## Требования

Для сборки и запуска приложения нужны:

- JDK 17;
- Android SDK 34;
- Android SDK Build-Tools 34.0.0;
- устройство или эмулятор с Android 7.0 (API 24) или новее;
- поддерживаемая архитектура устройства: `arm64-v8a` или `x86_64`;
- подключённое Android-устройство с включённой отладкой по USB либо запущенный эмулятор.

Для установки моделей потребуется подключение к интернету и около 1,5 ГБ
свободного места: GigaAM v3 — 229 МБ, диаризация — 43 МБ, локальная LLM —
1,04 ГБ. После установки распознавание, диаризация и правка текста работают
без сети.

## Сборка и установка

Все команды ниже нужно выполнять из папки `android`, в которой находится файл `gradlew`.

Перейдите в папку проекта:

```bash
cd android
```

Соберите APK:

```bash
./gradlew clean assembleDebug
```

Готовый APK появится по пути:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Установите приложение на подключённое устройство или запущенный эмулятор:

```bash
./gradlew installDebug
```

Проверьте, что устройство подключено:

```bash
adb devices
```

Перезапустите приложение:

```bash
adb shell am force-stop com.example.baseapp
adb shell am start -n com.example.baseapp/.MainActivity
```

Если приложение устанавливается вручную, APK можно передать на устройство и установить командой:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Готовый APK из репозитория ставится так же:

```bash
adb install -r artifacts/demo/app-debug.apk
```

Или просто скопируйте APK на телефон и откройте его в файловом менеджере
(нужно разрешить установку из этого источника).

## Первый запуск и модели

В приложении три модели, и все они не входят в APK — скачиваются один раз
при первом запуске. На главном экране для каждой есть карточка со статусом:
зелёная точка справа — готова, красная — нет.

1. Запустите приложение и дайте доступ к сети.
2. **Локальная LLM** (Qwen2.5 1.5B, ~1,04 ГБ) начинает скачиваться сама,
   без нажатий. Дождитесь надписи «Готова».
3. **GigaAM v3** (~229 МБ): нажмите «Скачать» на карточке.
4. **Диаризация** (~43 МБ): нажмите «Скачать» на карточке.

Загрузка идёт с прогрессом в процентах, файлы проверяются по размеру, а GGUF
ещё и по SHA-256. Если сеть пропала, нажмите «Повторить» — докачка начнётся
с места обрыва.

Для GigaAM есть и офлайн-путь: «Из файла» → выберите архив `.tar.bz2` —
приложение проверит SHA-256 и установит модель.

Пока LLM не скачана, приложение работает: текст правится rule-based
fallback (заглавные буквы и завершающая точка).

## Использование приложения

### Распознавание аудиофайла

1. Откройте приложение.
2. Нажмите «Импорт» и выберите аудиофайл.
3. Поддерживаются форматы WAV, MP3 и MP4. Для MP4 используется только звуковая дорожка.
4. Нажмите на загруженное аудио.
5. Нажмите «Распознать».
6. Дождитесь окончания обработки. Прогресс отображается на экране.

### Запись с микрофона

1. Откройте приложение.
2. Разрешите приложению доступ к микрофону, когда Android запросит разрешение.
3. Нажмите «Запись» и начните запись разговора.
4. Нажмите на записанное аудио
5. Нажмите «Распознать».
6. Дождитесь окончания обработки. Прогресс отображается на экране.

Запись сохраняется в формате WAV, моно, PCM 16 бит, 16 кГц.

### Просмотр и редактирование результатов

- Сохранённые расшифровки доступны на экране аудио по клику на него.
- Результат можно открыть повторно, изменить название и отредактировать текст.
- Изменения можно сохранить или отменить.
- Исходный текст распознавания, список слов и временные отметки сохраняются отдельно от вручную изменённого текста. Поэтому после редактирования временные отметки относятся к исходному распознанному тексту.

## Важные особенности

- Аудиофайлы и результаты распознавания обрабатываются и хранятся на устройстве.
- Интернет нужен для загрузки модели, но не для распознавания после её установки.
- Для записи аудио требуется разрешение `RECORD_AUDIO`.
- Для сборки Gradle автоматически загружает библиотеку `sherpa-onnx` версии 2.0.1. Поэтому при первой сборке также требуется интернет.

## Тесты

JVM-тесты приложения (63) не требуют устройства:

```bash
./gradlew testDebugUnitTest
```

Они покрывают форматы аудио, нарезку и тайминги слов, сборку сегментов,
экспорт JSON, цвета спикеров и проверку файлов моделей.

Instrumentation-тесты (декодер, Room, репозиторий, GigaAM) требуют
эмулятор или устройство:

```bash
./gradlew connectedDebugAndroidTest
```


## Локальная LLM

Приложение **само скачивает** Qwen2.5 1.5B Instruct Q4_K_M (~1.1 ГБ) при
первом запуске. Файл устанавливается сюда:

```text
/data/data/com.example.baseapp/files/models/llm/qwen2.5-1.5b-instruct-q4_k_m.gguf
```

В библиотеке есть карточка «Локальная LLM»: прогресс, проценты, кнопки
«Скачать»/«Повторить». Скачивание идёт в `cacheDir`, проверяется размер и
SHA-256, только потом файл переносится в `filesDir`.

Если сеть недоступна или модель не загрузилась, приложение не падает:
включается rule-based fallback (заглавные буквы и завершающая точка), а в
logcat по тегу `GigaAmTranscriber` видна причина.

Ручная установка (опционально):

```bash
adb shell run-as com.example.baseapp mkdir -p files/models/llm
adb push qwen2.5-1.5b-instruct-q4_k_m.gguf \
  /data/local/tmp/qwen2.5-1.5b-instruct-q4_k_m.gguf
adb shell run-as com.example.baseapp cp \
  /data/local/tmp/qwen2.5-1.5b-instruct-q4_k_m.gguf files/models/llm/
```

> Free-сборка `llama-android` содержит только `arm64-v8a`. На x86_64-
> эмуляторе LLM не загрузится; автоскачивание в этом случае отключается,
> остаётся rule-based fallback. Для реальной LLM нужен arm64-девайс.
