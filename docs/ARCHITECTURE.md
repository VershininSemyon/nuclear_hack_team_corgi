
# Описание архитектуры решения и применяемых моделей

## 1. Общая информация

Приложение предназначено для записи и загрузки аудио, распознавания речи, определения говорящих и сохранения результатов. Основная обработка аудио выполняется локально на Android-устройстве.

Проект разделён на несколько частей: пользовательский интерфейс, обработка аудио, распознавание и диаризация, а также хранение данных. Такой подход позволяет изменять отдельные части приложения без необходимости переписывать весь проект.

## 3. Архитектура приложения

В приложении используется разделение на уровни с применением паттерна MVVM (Model–View–ViewModel).

### Уровень интерфейса (View)

Интерфейс создан на Jetpack Compose. Основные экраны:

- библиотека аудиозаписей;
- экран информации о выбранной записи;
- экран распознавания;
- редактор расшифровки.

За переходы между экранами отвечает Navigation Compose. Основная навигация находится в `ui/AppNavHost.kt`.

### Уровень состояния и логики экранов (ViewModel)

Для экранов используются ViewModel. Они принимают действия пользователя, запускают операции через репозитории и передают состояние в интерфейс через StateFlow.

Основные ViewModel:

- `AudioLibraryViewModel` - работа со списком аудиозаписей;
- `AudioRecognitionViewModel` - запуск распознавания, отображение прогресса и сохранение результата;
- `TranscriptEditorViewModel` - редактирование расшифровки.

Долгие операции выполняются с помощью Kotlin Coroutines, чтобы не блокировать интерфейс.

### Уровень данных

Для хранения информации используется Room. Доступ к таблицам выполняется через DAO, а работа с данными приложения - через репозитории.

В базе данных хранятся аудиозаписи, расшифровки, слова с временными отметками и сведения о говорящих. Для сохранения и чтения данных используются сущности и DAO из пакета `data/db`.

`TranscriptRepository` отвечает за сохранение и получение результатов распознавания. `AudioRepository` работает с данными аудиозаписей. Для временного хранения черновика редактора используется `TranscriptDraftStore`.

### Создание зависимостей

Зависимости приложения собираются в `AppContainer` в файле `BaseApp.kt`. Это простой вариант ручного Dependency Injection: контейнер создаёт базу данных, репозитории и менеджеры моделей и предоставляет их остальным частям приложения.

Для создания ViewModel используются фабрики. Отдельного DI-фреймворка, например Hilt или Dagger, проект не использует.

## 4. Обработка аудио и распознавание

Обработка аудио выполняется в несколько этапов.

1. Пользователь выбирает аудиофайл или записывает звук через микрофон.
2. `AudioDecoder` извлекает звуковые данные из файла и преобразует их в массив аудиосэмплов.
3. `WavRecorder` отвечает за запись с микрофона. Запись сохраняется в WAV: моно, PCM 16 бит, 16 кГц.
4. `GigaAmTranscriber` управляет процессом распознавания и диаризации.
5. `com.nuclearhack.transcription.GigaAmTranscriber` запускает GigaAM v3 через sherpa-onnx и отдаёт слова с таймингами.
6. Длинная запись делится на фрагменты. Каждый фрагмент обрабатывается отдельно, после чего результаты объединяются.
7. Для распознанных слов формируются временные отметки начала и конца.
8. `com.nuclearhack.diarization.SherpaDiarizer` определяет интервалы говорящих; auto-K перебирает пороги 0.4–0.8 и выбирает устойчивое K.
9. `WordSpeakerAssigner` назначает каждому слову спикера по перекрытию интервалов.
10. `TranscriptionResultBuilder` собирает слова в реплики. Новая реплика начинается при смене говорящего или при паузе более 1,2 секунды.
11. При первом запуске `LocalLlmModelManager` автоматически скачивает Qwen2.5 1.5B (~1.1 ГБ) в `filesDir/models/llm`, проверяет размер и SHA-256. `LlamaCppLocalLlm` правит пунктуацию и очевидные ошибки каждой реплики. Если LLM нет/ошибка — остаётся rule-based fallback (регистр + точка).
12. Готовый результат сохраняется в локальную базу данных через `TranscriptRepository`.

Интерфейс распознавания получает текущий прогресс и отображает его пользователю.

## 5. Применяемые модели

### Распознавание речи

Используется **GigaAM v3 RNNT** (русский, ~229 МБ, int8). Файлы и их размеры
описаны в `GigaAmModelFiles`: `encoder.int8.onnx`, `decoder.onnx`,
`joiner.onnx`, `tokens.txt`. Архив скачивается с GitHub Releases sherpa-onnx и
проверяется по SHA-256; после распаковки размеры файлов сверяются с эталоном.
`GigaAmTranscriber` подаёт моно-аудио 16 кГц в
`com.nuclearhack.transcription.GigaAmTranscriber`, который режет его на
сегменты ≤ 25 с и собирает слова с таймингами.

### Диаризация

Используются две ONNX-модели из `DiarizationModelFiles`:
`pyannote/segmentation-3.0` для покадровой сегментации речи и
`3D-Speaker ERes2Net base` для эмбеддингов. Приложение использует
`com.nuclearhack.diarization.SherpaDiarizer`: несколько прогонов
`OfflineSpeakerDiarization` с порогами 0.4–0.8, выбор устойчивого K по плато,
затем `WordSpeakerAssigner` сопоставляет интервалы со словами ASR. В редакторе
спикеров можно переименовать и перекрасить.

## 6. Основные паттерны и принципы

В проекте используются следующие подходы:

- **MVVM** - разделение интерфейса, состояния и логики экранов.
- **Repository** - отдельный слой для работы с данными и базой Room.
- **DAO** - методы доступа к таблицам базы данных.
- **Dependency Injection** - передача зависимостей через `AppContainer` и фабрики ViewModel. Внедрение зависимостей выполняется вручную.
- **Factory** - создание реализации `Transcriber` через `TranscriberFactory`.
- **Интерфейс и реализация** - `Transcriber` задаёт общий контракт распознавания, а `GigaAmTranscriber` реализует его.
- **Observer** - `StateFlow` передаёт изменения состояния из ViewModel в Compose-интерфейс.

Это не строгая реализация Clean Architecture: проект использует её отдельные идеи, но слои и зависимости организованы проще.

|---|---|
| `BaseApp.kt` | Инициализация приложения и контейнера зависимостей |

| `audio/` | Запись, чтение, проверка и декодирование аудио |
| `data/` | Репозитории, модели данных, экспорт и черновики |
| `data/db/` | Room: база данных, сущности и DAO |
| `transcriber/` | Интерфейс распознавания и сборка результата |
| `transcriber/sherpa/` | Вспомогательные классы нарезки и таймингов |
| `transcriber/diarization/` | Старая обёртка диаризации (оставлена для совместимости) |
| `transcriber/model/` | Проверка, загрузка и установка файлов моделей |

| `com/nuclearhack/diarization/` | Research диаризация: SherpaDiarizer, auto-K, WordSpeakerAssigner |
